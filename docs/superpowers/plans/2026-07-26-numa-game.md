# Numa — Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browserbasiertes Multiplayer-Kartenspiel „Numa" (2–6 Spieler, PeerJS-Host-Modell, Bots, GitHub-Pages-Deploy) nach `numa-projektplan.md`.

**Architecture:** Reine, vollständig getestete Spiellogik als Host-seitiger Reducer (`src/game/`), dünne PeerJS-Netzwerkschicht (`src/net/`) mit Stern-Topologie (Host = Autorität, broadcastet Public State + private Hand), React-UI (`src/ui/`) mit SVG-Karten im dunklen Numa-Look.

**Tech Stack:** Vite, React 19, TypeScript, Vitest, PeerJS, reines CSS + SVG. Keine weiteren Libraries.

- Kein Redux/Zustand/Tailwind/MUI — nur React-Bordmittel + CSS
- Spiellogik (`src/game/`) ist pur: keine React-, DOM- oder PeerJS-Imports, deterministisch über Seed-RNG

## Verbindliche Regel-Interpretationen (wo die Anleitung schweigt)

Diese Entscheidungen sind im Sinne von Projektplan §10 getroffen (Detailfragen selbst entscheiden) und gelten für alle Tasks:

1. **Sitz-Konvention:** `players[]` ist die Sitzreihenfolge im Uhrzeigersinn. Linker Nachbar von Seat `i` = `(i+1) % n`, rechter = `(i-1+n) % n`. Bei 2 Spielern zeigen links und rechts auf denselben Gegner.
2. **Ablage-Reihenfolge = Sitzreihenfolge ab Startspieler** (jeder legt genau eine Karte, reihum).
3. **Schild/Spiegel sind passiv:** Sie werden in Phase B nicht „ausgeführt", sondern schützen ab dem Aufdecken die Person, auf die ihr Pfeil zeigt (self oder Nachbar). Jede Schild-/Spiegelkarte absorbiert bzw. reflektiert genau **eine** eingehende Aktion (erste zuerst; Schild hat Vorrang vor Spiegel, wenn beide dasselbe Ziel schützen). Selbst-gerichtete Aktionen des Besitzers werden nicht abgewehrt. Eine reflektierte Aktion trifft den Angreifer direkt (keine Ketten-Reflektion).
4. **Wertgrenzen:** `+`/`−` clampen auf 1–9.
5. **Fizzle-Regeln:** „Farbe kopieren" von farblosem Ziel bzw. „Wert kopieren" von wertlosem Ziel verpufft (Karte bleibt farb-/wertlos). `+`/`−` auf wertlose Karte verpufft. „Farbe tauschen" tauscht auch mit `null` (farblose Karte gibt „nichts" ab und erhält die Farbe des Ziels — Ziel wird farblos).
6. **Joker-Aktivierung:** aufgedruckte (nicht finale) Farbe der Begleitkarte == Farbe der aktuellen Regelkarte (beim „Neue Regelkarte"-Joker: der Vorschau-Regelkarte). Farblose Begleitkarte ⇒ Joker inaktiv. Ist die Vorschau schwarz ⇒ „Neue Regelkarte"-Joker inaktiv.
7. **„Alle Karten verschieben":** verschiebt nur die abgelegten Handkarten (mit ihrer Pfeilrichtung) eine Position in Jokerrichtung; die verschobene Karte zählt bei der Gewinner-Ermittlung für den Spieler, bei dem sie landet. Joker selbst wandern nicht.
8. **Mehrere gleiche Joker:** „Zweiter gewinnt" ×2 bleibt einfach aktiv; mehrere „Nur eigene Aktion zählt" ⇒ Vereinigungsmenge (nur Aktionen dieser Joker-Besitzer laufen); mehrere „Neue Regelkarte" schieben nacheinander weiter.
9. **Schwarze Regelkarte:** wird sie am Rundenanfang zur aktuellen Karte, gibt es statt einer Stichrunde eine Tausch-Phase (jeder wirft 0–7 Handkarten ab und zieht gleich viele nach), danach wird sie aus dem Spiel entfernt und die nächste Regelkarte aufgedeckt. Schwarze Karten im „Pool Extrem" zählen beim Abräumen als je 1 Punkt.
10. **Nur-Joker-Hand** (7 Joker, praktisch unmöglich): Spieler darf einen Joker als wirkungslose, farb- und wertlose Karte abwerfen.
11. **Wertung:** 1 Regelkarte = 1 Punkt (Pool-Karten inklusive). Punkteziel erreicht ⇒ Spielende (`∞` = nie).
12. **Wertlose Karten** können Paritäts-/Zahlenbedingungen nie erfüllen und verlieren jeden Zahlenvergleich; sind alle zulässigen Karten wertlos ⇒ Unentschieden.
13. **Mittel-Bedingung:** Distanz zu 5 (|v−5|), kleinere Distanz gewinnt; 4 vs. 6 ist Gleichstand.

      - run: npm run build
      - uses: actions/upload-pages-artifact@v3

    needs: build
    runs-on: ubuntu-latest
    environment: { name: github-pages, url: ${{ steps.deployment.outputs.page_url }} }
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
